# DMG の画面の色はどこから来るのか — 実機写真 10 個体の実測

*調査日: 2026-08-02 / brickboy 開発記録*

## この文書の位置づけ

brickboy は Game Boy エミュレータだが、主眼は**実機の液晶がどう見えていたかの再現**にある。その色設定が正しいのかを、実機の写真から検証した記録。

**結論を先に書くと、「brickboy の色が間違っている」という証拠は得られなかった。**途中で 5 回、もっともらしい結論を出しかけて撤回している。その過程も含めて残す。写真から色を語ることの落とし穴が、そのまま記録になっているため。

---

## 1. 疑問の出発点

開発者から「実機と比べて画質に決定的に足りない要素がある気がする」という指摘があった。何が足りないのかを、印象ではなく数値で特定しようとした。

---

## 2. 実機の構造 — 緑はどこから来るのか

まず、色を作っている物理的な層を確認した。

### リフレクタは銀色

日本語の分解記事に、実物の写真つきで明記されている。

> 剥がした箇所に**液晶裏面にこびり付いている銀色のモノが反射板**ですね
> 反射板はこのフラットケーブルの下にある**白いシート**
>
> — [ゲームボーイポケットの反射板の交換をしてみた（kill-time DX）](https://naokit.info/2025/03/10/%E3%82%B2%E3%83%BC%E3%83%A0%E3%83%9C%E3%83%BC%E3%82%A4%E3%83%9D%E3%82%B1%E3%83%83%E3%83%88%E3%81%AE%E5%8F%8D%E5%B0%84%E6%9D%BF/)

補修部品の商品名も "Back **Silver** Reflector"。**リフレクタ自体に色は無い。**

![DMG の液晶モジュール](images/dmg-panel/lcd-module.jpg)

*素の液晶モジュール。Photo: Raimond Spekking, [Nintendo Game Boy DMG-01 - LCD module-0004.jpg](https://commons.wikimedia.org/wiki/File:Nintendo_Game_Boy_DMG-01_-_LCD_module-0004.jpg), CC BY-SA 4.0*

### 色は偏光板と液晶の複屈折から

- **偏光板**: DMG は直線偏光フィルムを使い、これ自体が緑がかっている（補修部品の説明: "This film will have a **green tint** to it closer to the look of the DMG"）
- **STN の複屈折**: これが決定的だった。STN 液晶には「イエローグリーン・モード」と「ブルー・モード」という定番の 2 系統がある。

> the birefringence effect, which shifts the **background color to yellow-green** and the **character color to blue**
>
> — [Phoenix Display: Super Twisted Nematic](https://www.phoenixdisplay.com/technical-resources-category/super-twisted-nematic/)

**DMG はイエローグリーン・モード。**地の色が黄緑、点灯した画素が青寄りになるのは、液晶セルそのものの光学特性である。緑を出すのにリフレクタが緑である必要はない。

### まとめると

```
外光 → 前面偏光板(緑がかった直線偏光) → 液晶層(STN・複屈折)
     → 銀色のリフレクタ → 液晶層 → 前面偏光板 → 目
```

**「緑のリフレクタ」は存在しない。**地の黄緑は、無彩色の反射面に偏光板と複屈折の色が往復 2 回ぶん乗った結果。

## 3. 測り方

写真から色を語るのは危うい。露出・ホワイトバランス・カメラの彩度設定で見かけはいくらでも動く。次の 2 点を守った。

**線形光で測る。** sRGB のガンマを外す。暗い写真ほどガンマのせいでチャンネル比が誇張される。これを怠って一度誤った結論を出した（§7-③）。

**同じ写真に写っている無彩色の物を白基準にする。** オートホワイトバランスの効きを打ち消す。画面の外側で最も彩度が低い明るい画素を自動で拾う（多くは筐体か背景紙）。

指標は **G/R** と **B/R**。比なので露出には左右されない。

**この方法の限界: 絶対値では比べられない。**同じ実機の DMG でも、§4（電源オフ 10 個体）
では G/R 中央値 1.16、§5 の写真（電源オン・Tetris）では 2.45〜5.71 と、**2 倍以上ずれる。**
撮影条件・電源の有無・白基準の取り方で、この幅が出てしまう。
**信用できるのは同一画像内の傾きだけ**で、別々の写真の数値を並べて優劣を論じることは
できない。この文書で撤回した結論の多く（§7）は、この一線を越えたことが原因である。

再現用スクリプト: [`scripts/panel-color.py`](../scripts/panel-color.py)

```
python3 scripts/panel-color.py <画像>
```

## 4. 電源オフの個体 10 台を測る

リフレクタと偏光板の色をそのまま見るには、**何も表示していない画面**を見るのが正しい。Wikimedia Commons から自由ライセンスの写真を集めた。

![電源オフの画面 12 枚](images/dmg-panel/off-screens-contact.png)

*各写真から画面部分を自動検出して切り出したもの。左上（背景を誤検出）と上段2枚目（電源オン）は集計から除外。個々の出典とライセンスは §10。*

| 個体 | G/R | B/R |
|---|---|---|
| Game Boy frontal 2026 | 1.89 | 0.67 |
| Evan-Amos FL（スタジオ撮影） | 1.32 | 0.49 |
| Evan-Amos FR（スタジオ撮影） | 1.32 | 0.52 |
| Game-Boy-Original（スタジオ撮影） | 1.32 | 0.14 |
| Nintendo GB (1989) | 1.29 | 0.23 |
| DMG-01 | 1.03 | 0.05 |
| Spekking 0246 | 1.02 | 0.75 |
| 素の液晶モジュール | 0.96 | 0.56 |
| Original Game Boy | 0.93 | 0.42 |
| Game Boy originale | 0.81 | 0.19 |
| **中央値** | **1.16** | **0.46** |
| **brickboy（現状）** | **0.86** | **0.38** |

### 読み取れること

**青が全個体で強く抑えられている。** B/R は最大 0.75、中央値 0.46。**青が赤の半分以下。**「青成分を多く含む緑」のリフレクタは 1 個体も無かった。

**緑と赤はほぼ拮抗している。** G/R の中央値 1.16。強い緑ではなく、**黄土色にわずかに緑が乗った色**が実態。

**brickboy は実測範囲の中に収まっている。** G/R = 0.86 は観測範囲 0.81〜1.89 の内側（0.81 と 0.93 の個体の間）。B/R = 0.38 も中央値 0.46 に近い。

## 6. 濃度ダイヤルという変数

実機の DMG には側面に**濃度（コントラスト）ダイヤル**がある。「実機はもっと緑だった」という証言は、**ダイヤルを上げていた個体の記憶ではないか**という仮説を検証した。

### 物理的な裏づけ

パッシブマトリクスの STN では、ダイヤルは液晶への駆動バイアスを変える。バイアスは**点灯していない画素にも掛かる**ため、上げると地の色まで暗くなり、**画面全体が点灯時の色（＝素子の色）へ寄る**。明暗だけでなく**色が動く**。

brickboy はこれを次のように模している。

```glsl
if (uDensity > 0.5) {
  rgb = mix(rgb, uDmgPalette[3], (uDensity - 0.5) * 2.0);  // 全体を最暗の階調へ
} else {
  rgb = mix(rgb, uPanelBg, (0.5 - uDensity) * 2.0);        // 全体を紙の色へ
}
```

DMG プロファイルの階調3 は **(33, 92, 43)** という濃い緑。したがって**ダイヤルを上げると画面全体が緑に寄る。**

### 測定

`?density=` を振って、画面全体の平均を線形光で測った。

| 濃度ダイヤル | G/R | B/R | 平均輝度 |
|---|---|---|---|
| 0.30 | 0.93 | 0.41 | 0.274 |
| 0.40 | 0.97 | 0.42 | 0.240 |
| **0.50（既定）** | **1.00** | 0.43 | 0.214 |
| 0.60 | 1.06 | 0.45 | 0.184 |
| 0.70 | 1.12 | 0.47 | 0.156 |
| **0.80** | **1.18** | 0.49 | 0.136 |

![濃度ダイヤルの掃引](images/dmg-panel/dial-sweep.png)

*brickboy の出力。ダイヤルを上げるほど暗く、緑に寄る。0.80 では文字が読みにくくなり始める。*

### 読み取れること

**ダイヤルを上げると単調に緑へ寄る。** G/R は 0.93 → 1.18。

**§4 の実測範囲 0.81〜1.89 は、ダイヤルの位置だけでかなりの部分を説明できる**幅にある。ただし絶対値での対応づけはできない（後述）。

**B/R はほとんど動かない**（0.41 → 0.49）。ダイヤルを上げても「青みの強い緑」にはならず、実機の観測（中央値 0.46）と整合する。

### つまり

「実機はもっと緑だった」という記憶は、**ダイヤルを高めに設定していた**ことで説明がつく。読みやすさを求めて濃いめに合わせる人は多いはずで、その状態が「緑の画面」として記憶される。

**§4 で見た個体差の大きさも、パネルの違いではなく撮影時のダイヤル位置の違いである可能性が高い。**写真からはダイヤルの位置が分からないため、**この変数を無視して色を語ることはできない。**

なおこの表は画面全体（表示内容込み）の平均で、§4 の「地の色だけ」の数値とは母集団が違う。絶対値ではなく傾きを見るための表である。

### 階調ごとに何が起きているか

「濃くすると階調3 はあまり変わらず、階調0 がいちばん変わる」という証言を、診断 ROM の
階調ページ（4 階調が帯で並ぶ）で確かめた。

濃度 0.50 → 0.90 の輝度変化（線形光）:

| 階調 | 0.50 | 0.90 | 変化 |
|---|---|---|---|
| **0（最も明るい）** | 0.4145 | 0.1663 | **−60%** |
| 1 | 0.3156 | 0.1655 | −48% |
| 2 | 0.1709 | 0.1318 | −23% |
| **3（最も暗い）** | 0.1123 | 0.1008 | **−10%** |

色の変化も同じ順序（G/R、濃度 0.30 → 0.90）:

| 階調 | 0.30 | 0.90 | 変化 |
|---|---|---|---|
| **0** | 0.84 | 1.18 | **+0.34** |
| 1 | 0.99 | 1.26 | +0.27 |
| 2 | 1.05 | 1.25 | +0.20 |
| **3** | 1.04 | 1.21 | +0.17 |

**階調3 はほとんど動かず、階調0 が最も動く。**証言と順序まで一致した。

これは実装の式から必然的に出る。`mix(rgb, palette[3], t)` は**階調3 を不動点として
他をそこへ寄せる**ので、階調3 は自分自身と混ざって変化せず、いちばん遠い階調0 が
最も動く。偶然の一致ではなく構造的な一致である。

### 濃度をどこに合わせるか — 階調0 の見え方が基準になる

実機で遊んでいた人の証言に「**日本では階調0 がギリギリ薄く見えるくらいがちょうどよかった。
地域によっては階調0 がはっきりわかるまで濃度を上げないと見にくかった**」というものがある。

階調0 は濃度に**最も敏感な階調**（上表のとおり −60%）なので、設定の基準として理にかなう。
どこまで見えるかを測った。

| 濃度 | 階調0 のドットが地に対して見える度合い | 平均輝度 | 画面の G/R |
|---|---|---|---|
| 0.30 | 2.8%　ほぼ見えない | 174.9 | 0.87 |
| 0.50 | 2.8%　ほぼ見えない | 170.8 | 0.90 |
| 0.65 | 3.6%　ほぼ見えない | 148.8 | 0.99 |
| **0.80** | **6.0%　うっすら見える** | 124.4 | **1.08** |
| **0.90** | **8.1%　はっきり見える** | 111.9 | **1.16** |

「ギリギリ薄く見える」は濃度 0.65〜0.80、「はっきりわかる」は 0.90 付近に対応する。
**この 2 つの設定の間で、画面は 25% 暗くなり、G/R は 0.99 → 1.16 と緑寄りになる。**

**暗くなることと緑が増すことが同時に起きる**ので、印象としては「濃い緑の画面」になる。
設定基準の差が、そのまま見え方の差になっている。

なお「ギリギリ」「はっきり」は brickboy の描画に対するこちらのラベルで、**人間の知覚閾値を
測ったものではない。**実際の閾値は周囲光で動く。

### 「正しい濃度」は存在しない

以上から、**適正な濃度は視環境によって変わる**ということになる。実機に物理的なつまみが
付いていたのは、まさにそのためだろう。固定値で足りるなら付ける必要がない。

これは brickboy の設計判断に直結する。**「正しい既定値」をこちらで決めようとすること自体が
筋が悪い。**利用者の部屋の明るさとモニタの輝度で最適値は動く。brickboy は濃度を変えられる
口を持っている（画面左端のスワイプ）ので、既定値を動かすより、そちらに委ねるのが妥当と考える。

### この節の限界

以上はすべて **brickboy の挙動**の測定であって、**実機のダイヤルを回して測ったものでは
ない。**「実機はもっと緑だった＝ダイヤルが濃かった」という説明は、方向としては
辻褄が合うが、実機で検証したわけではない。

当初ここに「実機 10 個体の中央値 G/R 1.16 はダイヤル 0.75〜0.80 に相当する」と
書いたが、**撤回した。**絶対値の比較が成立しないため（§3 の限界を参照）。

## 7. 撤回した仮説の記録

**この節が本文書でいちばん実用的かもしれない。**もっともらしい結論が 5 回外れている。

### ① 「映り込み（sheen）が足りない」→ 却下

反射型液晶なので環境の映り込みが要る、と考えた。プロファイルの `sheen` が 0 になっていたのも根拠に見えた。

**却下理由**: 表示しているモニタ自体が既に環境を映している。疑似的な映り込みを描くと**二重になってかえって嘘くさくなる**。`sheen: 0` は正しい設定だった。

### ② 「乱数の種が大きすぎてシェーダが壊れる」→ 実測で否定

シェーダに `int(uSeed * 1013.0)` があり、32bit int を超えると未定義。プロファイル既定の種は 3〜9 なのに、ある機能で最大 21 億を渡していた。

**否定理由**: 種を 3 から 21 億まで振って実測したところ、基準との最大差 1.03、閾値超えの列は 0。**壊れていなかった。**

### ③ 「色の向きが実機と逆」→ 計算の誤り

「実機は暗いほど緑が抜けるが brickboy は逆」という結論を出した。

**誤りの原因**: `G−(R+B)/2` という指標を、**sRGB のガンマを外さずに**適用していた。線形に直すと**実機も brickboy も同じ方向**（暗いほど緑が強い）だった。

### ④ 「実機の地は G/R = 2.6 の強い緑」→ 標本の選び方が悪かった

電源オンの写真 1 枚から、実機の地は緑が赤の 2.6 倍、brickboy は 0.86 で赤優勢、と結論しかけた。

**誤りの原因**:
- その写真は EXIF が **彩度「強」・オートホワイトバランス**だった（EXIF を確認したのは指摘を受けた後）
- 比較に使ったもう 1 枚は **EXIF が完全に剥がされたブログ用の再エンコード画像**で、色の基準として使えるものではなかった
- 電源オフ 10 個体で測り直すと、実測範囲 0.81〜1.89 に対し **2.6 は外れ値**だった

### ⑤ 「明るい部分に格子が出ない」→ 解像度不足の見誤り

低解像度のブログ画像では、明るい背景に格子が見えなかった。

**誤りの原因**: 高解像度の元ファイルで見ると**はっきり出ている**。つぶれていただけ。

## 8. ロット・出荷国による違い

**調べたが、光学特性の違いを裏づける資料は見つからなかった。**

- DMG-01 には **8 種類のメインボード改訂**（DMG-CPU-01〜08）があり、LCD 基板・電源基板・ジャック基板にも改訂がある（[Game Boy Hardware Database](https://gbhwdb.gekkio.fi/consoles/dmg/) が個体ごとに追跡）
- ただし文書化されている差は **CPU・RAM の実装形態（エポキシ封止の有無）・電圧レギュレータ**であり、[Modding Fridays](https://moddingfridays.bleu255.com/Game_Boy_Types) も「LCD 基板の改訂は軽微な部品・レイアウト変更のみ」としている
- **ゲームボーイブロス**（1994-11-21 発売）は 6 色のカラーバリエーションで、パネルの変更を示す資料は見当たらない

§4 で観測されたばらつき（G/R 0.81〜1.89）は、**ロット差より撮影時の濃度ダイヤルの位置（§6）と経年劣化**で説明するほうが自然だと考える。正規化の基準にした筐体は経年で黄変するため、**黄ばんだ個体ほど補正が緑側へ効きすぎる**。背景が中性のスタジオ撮影 3 枚がいずれも 1.32 で揃っているのは示唆的だが、3 枚では確定できない。

### ハードの差ではなく、光環境の差で説明できる

パネルに差が無いとしても、**地域によって見え方が違うことは説明できる。**経路が 4 つあり、
**すべて同じ向き（明るい地域ほど緑が濃く見える）に働く。**

**① Hunt 効果 — 明るいほど色が濃く見える**

色度が同じでも、輝度が上がると人は色みを強く感じる（R.W.G. Hunt, 1952。CIECAM02 に
組み込まれている標準的な色の見えモデルの一部）。

> The Hunt effect comprises an **increase in colorfulness of a color with increasing luminance**

反射型液晶は戻る光量が周囲光にそのまま比例する。日射の強い場所では戻る光が桁で増え、
**同じパネルが物理的に同じ色を返していても、緑が濃く見える。**

**② 表面の映り込みとの比率 — 光の当たり方で彩度が変わる**

戻ってくる像の光は液晶を 2 回通った着色光、表面の映り込みは無彩色。この比率で彩度が決まる。

- 強い直射光: 太陽が画面を照らし、表面に映るのは相対的に暗い空 → **着色光が優勢＝色が濃い**
- 屋内の拡散光: 照らす光と映る光がどちらも天井から来る → **無彩色が混ざって色が薄い**

**③ 光源のスペクトルが違う**

液晶スタックは往復 2 回ぶんの狭帯域フィルタで、透過率が 2 乗になるぶん光源スペクトルの
凹凸を強く拾う。DMG の時代、日本の家庭の照明は蛍光灯が主流だった。蛍光灯には水銀の輝線
（405 / 436 / **546** / 578 nm）が乗り、**546nm は緑の輝線**である。連続スペクトルの
太陽光と、輝線の立った蛍光灯とでは、同じフィルタを通しても出てくる色が違う（条件等色）。

**④ 濃度ダイヤルの設定位置**

明るい場所では表面の映り込みで階調が潰れるため、濃度を上げて差を広げ直すことになる。
§6 のとおり、濃度を上げると画面は暗く・緑寄りになる。

### 測定にとっての含意

**Hunt 効果は撮影者の目には効くが、カメラのセンサには効かない。**一方、**光源スペクトルの
違いはセンサにも効く。**つまり §4 の分布（G/R 0.81〜1.89）は、パネルの差ではなく
**撮影環境の差を測っていた**可能性がさらに高い。

**「唯一の正解値は存在しない」という結論が、より強く裏付けられたことになる。**

**パネルの差については未解決。**製造時期の分かる個体を、条件を揃えて撮って比べる必要がある。
ただし上記のとおり、**差を説明するのにパネルの違いを持ち出す必要はない。**

## 9. 結論

**brickboy の画面色を変更する根拠は得られなかった。**現状の G/R = 0.86 / B/R = 0.38 は、実機 10 個体の観測範囲の内側にある。

分かったこと:

- **リフレクタは銀色**で、色は持たない
- 地の黄緑は**偏光板の色と STN の複屈折**から来る（イエローグリーン・モード）
- 実機の画面は**青が赤の半分以下**。「青みの強い緑」ではない
- **濃度ダイヤルを上げると画面全体が緑に寄る**。実機の中央値はダイヤル 0.75〜0.80 相当
- 実機どうしのばらつきは**撮影環境と濃度ダイヤルの位置**で説明できる。**唯一の正解値は存在しない**
- **適正な濃度は視環境で変わる**（Hunt 効果・表面反射・光源スペクトル・ダイヤル設定の 4 経路が
  すべて「明るい地域ほど緑が濃く見える」方向に働く）。実機に物理的なつまみが付いていた理由でもある

残る課題:

- **実機での検証**。診断 ROM（`public/roms/check.gb`）は実機で動く。フラッシュカートで
  実機の DMG に表示して撮れば、**同じ内容**を並べられる。4 階調が帯で並び、5 ページ目は
  全ドット点灯なので、階調ごとの直接比較ができる。写真から色を語るときの不確かさ
  （露出・WB・彩度・被写体違い）が、これでほぼ消える
- **残像の時定数**。brickboy は緩和側 61ms（`8 + 102 × ghost.strength`）。同時代の STN モジュールは 100〜200ms とされる。実機映像から尾の長さを測れば客観的に詰められる
- **ドットの硬さ**。実機は縁が柔らかく影が無い。拡散反射面での光の回り込みを模していない可能性

写真から色を決めるなら、**ホワイトバランス固定・彩度標準・同じ画面内にグレーカード**で撮った実機の写真が要る。それが無い限り、この種の議論は堂々巡りになる。
